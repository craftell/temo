# 0.5.0

Prepared with definition deletion and modal interactions. This document does not publish a release.

- Add a delete-definition confirmation on `D`, with Cancel selected by default.
- Require a fresh stopped status before saving the deletion. Active, retained-ownership, pending, unknown, and error states cannot be deleted. Use `x` to stop and release ownership first.
- Keep forms, details, help, config location, and SSH host selection in centered modals over the route list. Esc returns one level without discarding an underlying form.
- Keep the current filter and select a neighboring route after deletion. Preserve focused fields and modal navigation through terminal resizing.
- Reload configuration after a failed save. Block further changes if the persisted outcome cannot be read.

Backend start, stop, ownership journals, and self-update keep their existing behavior. Deletion removes only a saved definition after confirmation. It does not stop a connection or delete an ownership journal.

The release workflow requires the approved tag to match VERSION. An authorized maintainer can create v0.5.0 on the intended tested commit after merging. This change does not create that tag or publish assets.
